# 检索与资料验收流程

本页记录 0.6.2–0.6.6 的重建和验收方法。各次发布的快照和性能应分别核对，不把旧实验数字当作新版本实测。已发布的 0.6.1 有 6 个来源、1,830 条候选卦例、4,067 个原文块；0.6.2 进一步按原文中的六亲定义小节切分并修复跨页图关联，0.6.2 与 0.6.4 冻结库均为 4,098 块、1,834 例。当前 OCR 台账共 964 条（836 条未核准机器建议、128 条经 PDF 核准并应用的修订）。其中本轮追加 27 条图表与日期校订，配合跨页关联修复，重新核对《象法进阶》上册 145–146 页的三例；已发布版的 7 个具名修复也继续回归检查。这些数字是建库快照，不是全部资料、检索质量或预测效果的最终验收结论。最终应以冻结后的 `release-manifest.json`、测试记录及其哈希为准。

## 原文、校订与结构字段

`data/sources.jsonl` 是唯一的入库来源清单，记录来源 ID、路径、标题、类型和文件 SHA-256。原生文字稿按实际正文、日期和六爻排列提取；不能因为没有经过 OCR 就默认排盘正确。OCR 稿保留初始转写及 PDF 页锚点，机器对照只产生待核对线索。

- 行内修订记录在 `data/ocr_corrections.json`，必须有原稿哈希、原行号、字符起止位置、改前/改后文字及 `visual_verified`。仅原图核准的条目进入正文覆盖层；修订不增删换行，保留目录和证据行号。锚点或哈希不符时停止重建，先回查来源版本。
- 逐字整页稿存于 `data/proofread_pages/<source_id>/<page>.json`，记录 PDF 与原稿哈希、实际 PDF 页码、完整校订文字、方法和疑点。`unclear` 保留图像残缺，不能猜填。整页稿和行内覆盖层是两种产物；核准一页不会自动替换所有结构字段。
- `get_source(evidence_id)` 默认返回校订正文及其 `source.sha256`；`text_version="original"` 返回原转写及原稿哈希。`source_spans` 是该版本正文中的一基行号，文本按 Python 通用换行规则读取。引用应同时保留来源 ID、版本哈希、证据 ID 和行段，不能只抄一段文字。
- OCR 证据的 `page_reviews` 区分机器对照、逐页核准和未审页。有页面证据 ID 时，`get_source("page:来源ID:PDF页码")` 可读整页校订稿及其 `text_sha256`、`pdf_sha256`、`original_sha256`。该入口不支持 `text_version="original"`，原稿应从普通证据入口回查。
- PDF 实际页码、目录印刷页码、书内印刷页码分别保存。目录标题经过核对不代表对应正文已经补齐；正文缺失仍须报告。

六爻从初爻到上爻统一为 0 老阴、1 少阳、2 少阴、3 老阳。抽取后重算六爻、纳甲、世应、本变卦并核对原文明确声称的盘面；缺月日、爻值不全或相互矛盾时保留 `partial`、`unknown` 或冲突字段，不继承上一卦日期，除非原文明确写明“同日”。`chart_validation="calculated"` 只说明可重算且通过当前一致性检查，不说明作者断语或反馈已获独立验证。检索与原文回查均不会把冲突或未校验案例的内部计算盘作为可信结构返回；`get_source` 以 `computed_chart_omitted` 说明省略原因，原文、作者声称的盘面与冲突记录仍保留。当前结构字段来自校订版本的解析；`text_version="original"` 切换的是原文显示。

## 重新切块和重建检索

修改源稿覆盖层、解析器、分词、分类或目录后，须重新入库；只修显示文字或只更新向量会让搜索继续使用旧字段。

```bash
python -m liuyao_mcp.ingest --root . --output data/knowledge.sqlite
python -m pytest tests/test_ingest_boundaries.py tests/test_retrieval_regressions.py tests/test_packaging.py
```

重建会写出同目录的 `cases.jsonl` 和 `ingest_report.json`，重新切分相邻卦例、章首、独立日期及卦例前后的论述，并重建 FTS5 与 发行版本对应的筛选字段（0.6.5 起为 `focused-3`）。每个 `case_excerpt` 原文块最多关联一个卦例；只有排盘标题、没有个案分析的片段不作为理法证据召回。自序、广告等 `background`、纯盘面 `chart_only` 和没有正文的纯标题 `heading_only` 保留原文回查与目录，但不参与规则召回。带有完整断语的标题和单行六亲定义仍须保留，不能仅按行数或目录锚点删除。`content_role="theory"` 表示论述片段，仍需核对其适用条件；`kind="rule"` 是检索入口，不能据此把个案解释当成公共通则。使用 `python scripts/audit_knowledge_index.py` 全量核对词法索引、来源行段、盘面状态和筛选字段。

案例索引使用占问及可验证盘面条件，不把作者解释、反馈结果或期望答案加入案例召回文本。自动事项分类有依据字段，但仍需人工核对原问；默认 `include_unknown=false`，显式打开后才接纳未分类候补。传入 `features` 或 `require_valid_chart=true` 时，仅比较 `chart_validation="calculated"` 的案例。未知用神、空破或动静条件不要填为 false。

检索时检查返回的 `query_terms`、`query_negations`，确认生活问法、六爻术语和否定条件进入了正确的检索表达。除明确停用词外，不按字数丢掉单字：例如“子孙化鬼”须保留“子孙、化、鬼”。“外应”“内应”等独立概念进入术语词表，不能退化成“应爻”；修改词表后必须重建 FTS。当前六来源中没有字面“外应”材料，词法无命中应明确报告；语义返回内外卦的相近文字也不代表覆盖了该方法。观察 `returned_count`、`has_more` 和 `budget_skipped`；按当前证据缺口选择数量、扩大文字预算或续读原文，不设固定论述/卦例配额。排名、向量相似度、重排分数都不是正确率或概率。

## 真实向量、CPU 推理和缓存

默认发布 wheel 随包提供数据库，BM25、排盘和原文查询不需要模型或 API Key。本轮使用真实 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3` 模型；0.6.2 冻结库完成 5,891 份非空文本、5,951 个窗口向量构建，41 个空文本 ID 在清单中保留。已逐项核对全部向量的缓存、数值、全文窗口覆盖与 22 张来源表的一致性，并实测规则/案例的三种模式和 30 项引文。相关性与解释者的盲测另行评价，不能把索引写出当成预测验证通过。

需要语义检索时，在安装了本项目 `dense` 依赖的同一 Python 环境执行：

```bash
python -m liuyao_mcp.semantic prepare
python -m liuyao_mcp.semantic warm
python -m liuyao_mcp.vector_index --database data/knowledge.sqlite
python -m liuyao_mcp.semantic activate
python -m liuyao_mcp.semantic health
```

源码环境可传 `--database`；wheel 用户从任何目录运行 `python -m liuyao_mcp.vector_index`，使用随包数据库，无需克隆仓库。`activate` 在规则、案例的真实向量检索均通过后，把运行目录的 `data/retrieval-config.json` 切到 `hybrid`；只有显式传 `activate --mode hybrid_rerank` 才启用重排。已有用户配置不会自动改写。索引缺失或语料/模型版本不匹配会报错，不静默伪装为语义检索。CPU 实测、精度选项与扩容方法见[CPU 检索性能与扩容](CPU检索性能与扩容.md)。

模型名、revision、文件 SHA-256 和缓存路径写入 `.local/models.json`，下载中断可续传，缓存复用前校验权重。运行库版本也进入模型键。编码为 CPU float32、1024 维、CLS 后 L2 归一化，长文本按 token 窗口覆盖；每条缓存记录向量及文本窗口范围，不生成假 embedding，不用零向量补空项。只含空白的资料不参与编码，索引清单保留被排除 ID。

每条编码缓存由模型/运行库/索引设置及文本哈希决定，保存在 `data/semantic-index/cache`。修改语料后重跑向量命令会复用未变文本，重新编码变化部分；全部成功并写出同库向量快照后才更新 `active.json`。传 `--no-activate` 可只生成独立候选快照，用于验收而不切换当前索引。保留缓存、进度和模型锁即可续建。发行包用户的运行状态放在用户缓存目录（Windows 为 `%LOCALAPPDATA%/liuyao-mcp`，其他系统按 `XDG_CACHE_HOME` 或 `~/.cache/liuyao-mcp`），独立于 uv 临时环境；源码开发环境使用当前工程目录。

CPU 编码和重排共用持久计算执行器，避免短命请求线程反复创建原生线程资源。本轮 350 条不同文本的编码试验中，Windows 进程私有提交内存从约 6,206 MB 到 6,213 MB；旧实现曾达到 110,523 MB。这是该负载下的资源回归证据，不是全库性能承诺。需要停止推理时运行 `python -m liuyao_mcp.semantic stop`，随后核对进程退出；不会删除模型和编码缓存。不同开发工程使用不同 `LIUYAO_INFERENCE_PORT`，服务会核对运行根目录和模型键，避免复用另一个工程的进程。

## 外部案例与防止答案进入评测输入

`data/evaluation/` 与 `data/sources.jsonl` 分离。初始外部样本有 14 条开发例和 13 条留出例；13 例已在预测冻结后揭盲评分并退役，后续新增的 8 条原生文字案例也已完成成对盲测并退役。不得再把这些样本称作未见测试集。具体来源、原文行段及 SHA-256 存于键文件和验证清单。它们不进入主知识库、FTS 或向量，不属于 wheel 的可检索资料。留出集还按书籍/作者及事件分组隔离，以降低同源改写泄漏。

开发输入 `development.blind.jsonl` 只给问题、时间、六爻和程序盘面；反馈、作者判断、精确原文和来源身份留在 `development.key.jsonl`。留出输入与 `holdout.key.sealed.jsonl` 分开保管。验证来源时核对原文件哈希、原文行段、反馈位置和盘面签名，并检查主库重复案例及连续文字重合；疑似改写与重合项先人工排除或单列，不只依靠文件名判断“库外”。

先在开发例上定位分词、召回或结构匹配问题。检索评测记录查询、语料/模型哈希、候选及工具轨迹；同事项命中和覆盖度只是检索指标。解释盲测先冻结工具、语料、提示和评分准则，再让解释者只读取盲输入，输出后才由独立评分者读取键文件，分别评主结果、时间和可选细节，保留弃答及反馈矛盾。若查看留出答案后改动实现，这批样本只能作为下一轮开发数据，下一次结论需要新的封存来源。

独立 Astra xhigh 任务已完成：旧 13 例的两版本均为 5/12 可评分主方向相符；新 8 例在检索与仅排盘两种条件下均为 7 相符、1 有效弃答。本次没有观察到检索带来断卦增益，不能跨样本比较得出版本提升。见[0.6.2 评测](评测结果-0.6.2.md)与[0.6.4 成对评测](评测结果-0.6.4.md)。历史书籍反馈未独立验证，方向一致也不表示细节或应期正确。

以后加入新资料：先保存来源文件、哈希和可回查行页，明确它属于检索资料还是封存评测资料；完成原生/OCR格式与抽取检查后，只有检索资料可登记进 `sources.jsonl`。若加入曾用于评测的来源或同案改写，先退役受污染样本并建立新留出集，再重建正文、FTS、分类和向量；不得用留出反馈扩词、调排名或编写答案模板。

## 冻结、打包和用户交付

0.6.5 另增加了分层用神接口与盘式事实；它们属于上游独立变更，0.6.4 的冻结书例预测不覆盖这些新增接口。最终合并版本须保留其公开接口并运行对应回归检查。

发行包版本取自 `src/liuyao_mcp/__init__.py`，构建时须与待发布版本一致；`PARSER_VERSION`（0.6.5 起为 `source-parser-0.7`）标识抽取格式，独立于包版本，实际实现变更另由 `implementation_hash` 和 `corpus_hash` 绑定。插件与包版本一致，不能用包版本号代替数据库一致性检查。

先保存已验收数据库的 `build_info.corpus_hash`，再按相同语料重新生成发行数据库。哈希不一致时不继续构建：

```bash
python scripts/build_release.py --expected-corpus-hash <已冻结的corpus_hash>
python scripts/smoke_release.py --wheel dist/liuyao_mcp-<版本>-py3-none-any.whl
```

构建产物包含 wheel、源码包、插件 ZIP、安装脚本、`release-manifest.json` 和 `SHA256SUMS`。清单记录源稿哈希、建库实现哈希、数据库哈希及计数；wheel 只内置主库，不捆绑机器模型缓存或评测答案。安装冒烟从临时工作目录通过 `uvx` 启动本地 wheel，清除工程路径覆盖并隔离用户模型配置，核对实际 `site-packages`、版本及随包数据库 SHA-256，并走真实 MCP 验证分词、否定、事项、有效盘面筛选、标题排除、相邻卦例边界、OCR 前后版本及出处。脚本禁止隐式下载 Python，使用当前已有解释器。

拿到 wheel 后，用户可从任何目录直接启动，无需源代码或 PDF：

```bash
uvx --python 3.11 --from /path/to/liuyao_mcp-<版本>-py3-none-any.whl liuyao-mcp
```

发布后核验实际 GitHub Release 资产，使用插件内固定版本命令，并执行 `python scripts/smoke_release.py --plugin`。源码测试成功、Python 模块可导入、MCP 在当前 Codex 任务中注册是三个不同检查；新安装/更新后仍需在新任务里确认工具可调用。正式资产、CI、安装检查和当前任务的工具注册须分别记录；测试报告保留尚未覆盖的资料与语义相关性限制。
