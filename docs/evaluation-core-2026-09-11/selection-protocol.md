# 核心理法／象法独立评估选例协议

本协议在读取本次候选案例反馈前写定。本轮仅检验已人工整理、原图校订的核心规则应用，不是六书全库效果验证，不替代后续全库及相似案例检索的独立验证。判断所复现的是书中记载，尚无现实独立核验。

## 固定范围与顺序

1. 理法仅使用 `data/manual_slices/shards/liuyao_lifa_jinjie/0143-0146.json`，按原文位置顺序选前 3 个合格且事件不同的案例。
2. 象法仅使用 `data/manual_slices/shards/liuyao_xiangfa_jinjie_shang/0186-0194.json`，分别为核心用法 01、02、03 选原文顺序第 1 个合格且事件不同的案例。用法归属由原文内容与规则关联确定，禁止按结果是否好预测进行选择。
3. 合格条件：真实事件案例；每次参与判断的起卦有完整六值和月／日；有明确可区分于作者断语的原文反馈。两卦同一事件仍只算一例，保留所有必要起卦。
4. 候选不合格时记录明确原因；不从其他段落补例。不因与规则相反、作者错判、预测难度或结果复杂而排除。

## 输入与封存

- 匿名输入只含 `anonymousID`、`question`、`known_background`、`casts`。保留原始占问，以及来源中已有且起卦时已知的年月日时、公历和背景；不为迎合结果改写提问。
- 排除所有 `eligible_for_initial_blind_input=false` 字段，以及在首断后才披露的信息。不能判定当时已知的背景不进入盲输入，并在封存参考记录处理理由。
- 输入不含作者书名、原始 caseID、原断语、反馈或适用法标签。匿名序号采用固定种子洗牌，顺序不编码理法／象法类别。
- 私有 `sealed-key.json` 保存原文 span、完整引文与 SHA-256、unitID、案例映射、原断语、明确反馈、作者推理步骤及适用条件／限制。预测锁定前不得把结果回传给解释者或主任务。
- 不新采案例，不读旧评分，不修改产品实现，不启动预测。

## 评分边界与来源审计

- 未来分别评估：核心规则是否适用；太极点、用神、旺衰、动变和六神的使用是否有原文来源；是否处理相反证据；结果、时间与细节是否符合明确反馈。
- 原作者错判不能当作事实 gold；首断后的信息和事后解释不能算首断时可预知的证据。无明确结果的维度留空，不以作者确信程度替代事实。
- 审查实际提供给解释者的 rules-only 规则、`required_contexts` 与检索响应。仅因直接泄露所选目标事件答案而建议排除 ruleID，不因反证或难题而排除。其余规则若相关也保留；不得开放 case/page/book 原文或任意 `context_lines`。
- 向主任务回传不含答案的排除／来源审计摘要、输入和 key 的 SHA-256、选中数量与完整性。最终揭晓必须等待独立 Astra 预测锁定。
