日期：2026-09-10。状态：基于现有两册OCR与数据库核对后的设计方案，尚未改动入库程序或发布新的检索功能。

用户确认的方向：理法和历史案例可按占问大类、小类组织；象法不再增加“姻缘／学业／健康”等事项分类体系。象法沿用书中的知识目录，以实际场景和盘面线索检索。书中某条用法已有事项限制时，保留原文条件，但不把整段知识锁进某个事项类别。

## 2. 用原书目录导航，用场景定位具体用法

索引层次为：`册 → 章 → 节（如有）→ 原文编号用法（如有）→ 论述与关联案例`。不强行为没有节或编号的章节增加虚构层级。

例如朱雀一节，正文已经按编号讨论不同用法。可以建立这样的导航，最后一层文字是索引概括，不冒充原书正式小标题：

```text
上册
└── 第一章 六神之象
    └── 第二节 朱雀
        ├── 第1类用法：口才、交谈、谈判等
        ├── 第2类用法：不利情境下的言语表现等
        ├── 第3类用法：文书、考试、成绩、合同、消息等
        └── 第4类用法：发热、炎症等相关表述
```

其中第3类用法在上册第2720—2724行，PDF第66页。紧接着第2728行就是“论文送审能否一次性通过”的案例。这说明目录能够把一段用法和用于说明它的案例关联起来，无需另外给整个朱雀节限定“学业类”。

场景保留为可检索的短语与描述，例如“材料审核”“信息传递”“口头沟通”“等待消息”。不设置固定的场景分类树，不把场景短语作为排他过滤条件。短语应来自原文概括或用户已提供的背景，保留概括依据，不能根据最终反馈倒推本次占问的事实。

## 3. 保存哪些结构化信息

新增目录节点表`outline_nodes`，保存节点ID、父节点ID、册与来源、目录顺序、原始标题、展示名称、名称来源、原文范围、PDF页码和解析状态。新增`evidence_outline`关联表，把现有知识块与案例ID关联到目录节点。

目录节点ID使用稳定的册／章／节／用法编号；标题纠错只调整展示名称与别名。当前`chunks.chapter`可以暂时保留为兼容展示字段，新查询使用完整路径，避免只剩最后一个节名。

一个拟新增的用法节点示例如下，示例不是已经导入数据库的记录：

```json
{
  "node_id": "xf_shang_c01_s02_u03",
  "parent_id": "xf_shang_c01_s02",
  "source_id": "liuyao_xiangfa_jinjie_shang",
  "node_type": "usage",
  "ordinal": 3,
  "title_raw": null,
  "title_display": "文书、考试、成绩、合同、消息",
  "title_basis": "summary_of_numbered_paragraph",
  "anchor_span": {"start_line": 2720, "end_line": 2724},
  "anchor_pdf_page": 66,
  "scene_hints": ["材料审核", "信息传递", "论文送审"],
  "context_refs": [
    {"start_line": 2091, "end_line": 2094},
    {"start_line": 2720, "end_line": 2724}
  ]
}
```

`title_raw=null`表示原书这里是编号段落，没有单独的小标题；展示名称是检索概括。`anchor_span`定位该用法的解释开头，完整用法范围由下一用法边界确定，包含其配套案例。场景短语与目录名称均为辅助索引，引用仍使用原文。

每条返回证据应包含：目录路径、原文、适用条件所在段落、关联案例ID、出处、已匹配的场景或盘面线索，以及尚不能确认的条件。章节范围较长时，按现有长度预算和续读机制返回。

## 4. 查询时怎样组合目录、场景和盘面

以“面试中沟通不顺，想了解对方态度”为检索场景示例，不预设结果：

1. AI保留用户已说明的场景，形成“沟通、表达、答复、材料”等查询表达。
2. 按理法先核对所问对象和关键爻。若关键爻涉及朱雀，就查“六神之象／朱雀”；若有已确认的旬空或伏神线索，再补查“旬空之象”或“伏神之象”。
3. 场景检索可以跨章节寻找候选，目录检索负责定位概念及上下文；两个入口并列，不能要求先命中某目录才允许检索正文。
4. 读取具体用法时补回必要的节／章导语与同一用法的限制，随后查关联案例，并比较本次问题是否满足条件。
5. 根据证据缺口由AI调整数量、去重补查；证据足够时停止。目录命中只表示需要查证，不能直接从“朱雀”“旬空”等名称生成事件结论。

六神在完整盘面中都会出现，所以不能因为盘里“有朱雀”就把朱雀整节搬入回答。要结合关键爻、用户场景及具体疑点选择条目。

第一阶段只使用现有排盘可提供的六神、六亲、动静、伏神、旬空和本变卦信息辅助目录定位。长生十二宫、三刑、反吟、隔山化区等章节可以被场景和概念查询命中，但当前程序尚未完整计算这些组合的适用条件，不得标成已自动验证的触发事实。

书中原文若限定“在某种卦象条件下”或“结合爻位、六亲”等，应返回这些限定。比如朱雀节开头在第2093—2094行就区分不同卦象条件，第2723—2724行再次要求综合核对；第十一章第7115—7117行明确将卦象含义定位为参考。不能只截取一个象义词条。

## 5. 与理法分类如何协作

- 理法路径：占问大类／小类 → 对应理法＋适用的公共理法 → 核对盘面条件。
- 象法路径：原书目录＋已知场景＋关键爻线索 → 具体用法与配套案例。
- 同一案例可以被两条路径引用；案例已存的事项信息保留给理法路径使用，象法查询不以事项大类作硬过滤。

现有`search_knowledge`会对case查询从问题中推测`topic`并筛选案例。后续实施时应明确拆开两条策略，使`method="xiangfa"`不再自动套用这一事项过滤，否则跨场景的象法案例仍可能被提前排除。

拟扩展接口：

- `get_outline(source_id, parent_id=None)`：读取某册目录或某节点的直接子节点，返回目录ID与原文锚点，方便AI先定位章节。
- `search_knowledge(method="xiangfa", query=场景描述, outline_ids=可选目录范围, limit=AI选择的数量)`：场景查询默认覆盖象法资料；已明确目录时再缩小范围。
- `get_source`继续按证据ID回查原文，并利用目录关联提供所需导语与邻近用法。保留分页和内容长度限制。

第一版可以复用BM25，把目录路径、检索别名、场景短语与正文一起用于召回；不需要先实现structure_vector。是否增加场景语义向量，后续根据具体漏检样例评估。

## 7. 实施顺序与验收

1. 先建立两册目录清单，用正文标题、章内说明、编号用法和页码定位；目录页仅作辅助。原图未核对的纠字与推断边界保持显式状态，不补造缺失标题或印刷页码。
2. 在目录边界内重新切片，保护完整段落与六爻图；关联章节导语、用法段落和对应卦例。目录、前言与案例内容分开标识，避免目录残文污染正文检索。
3. 写入目录节点与证据关联，重建全文索引；原书OCR正文保持不变，纠字只进入展示名称／别名，保留可回查的出处。
4. 接入目录浏览与象法场景查询，移除象法路径上的事项硬过滤；更新AI指引，要求读取条件和对应案例。

验收至少包括：

- 上述腾蛇、墓、艮宫三处定位不再继承错误章节；不确定的恢复节点仍有依据和状态。
- 查询“沟通、文书、材料审核”等场景时可以定位到朱雀节中的相关用法，返回其目录路径和原文条件。
- 同一象法用法可被不同事项的相关场景检索到；没有目录约束时保留全体象法资料的召回入口。
- 关联案例的原文范围、PDF页码及来源哈希可以回查；推断性目录名称与作者原文不会混淆。
- 检索数量继续由AI主动设置，不以固定条数或读完整章作为完成标准。

本阶段交付的是可靠目录和场景检索能力。不会把作者举例当成已验证的事件规律，也不会把目录恢复等同于完成所有象法格局的自动推导。
