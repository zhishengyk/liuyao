# 分类与格局实现说明

0.6.0把事项分类、盘面结构和原文出处接入同一套查询。默认仍使用本地SQLite BM25与结构匹配，无需查询编码器。

## 理法与卦例：大类 → 小类

`get_topics()`列出14个大类；`get_topics(topic="relationship")`列出其小类和证据数量。分类节点与证据之间用SQLite关联表保存，一条证据可对应多个事项。

```python
get_topics(topic="relationship")
search_knowledge(
    "复合 世应 官鬼",
    kind="case", topic="relationship", subtopic="relationship/reconciliation",
    features={"shi_ying_relations": ["冲"]}, limit=6
)
search_knowledge(
    "复合 用神 旬空",
    kind="rule", method="lifa",
    topic="relationship", subtopic="relationship/reconciliation",
    include_common=True, limit=8
)
```

这里的数量只是单次调用示例，由AI根据证据需要调整。

排序先考虑同小类，再回退同大类、公共理法和明确标注的未分类候补；各层内融合关键词与结构匹配排名。结构条件可以独立召回，不要求同时命中关键词。`include_common`控制公共理法能否参选，不保证某次结果包含公共理法；需要通用依据时可不加事项条件另查。

`classification`保存原文匹配词、分类来源和状态。案例优先用原始占问，必要时继承明确的理法章节主题；不拿作者结论或反馈反推分类。理法中的通用章节保持`common`，不会因为举例涉及某种事项而变成该事项专属规则。无依据的条目标`unknown`，不伪装成公共规则。多事项占问可以分别查多个分支。

自动标签属于可解释的初始标注，并非全部案例已准确分类。当前构建的1,548条候选卦例中，993条得到至少一个事项标签，555条仍未分类；部分经典短问和OCR残缺需要继续校订。完整的是两级分类与查询机制，未宣称语义标注已经逐条核准。

## 象法：原目录、场景与结构

象法不套事项分类过滤，`method="xiangfa"`会忽略`topic`和`subtopic`。`get_outline`浏览原书目录；`outline_ids`限定目录及后代，场景查询可以跨章。盘面字段提供六神、世应、六亲、旬空、动变和伏神，AI据此选择相关用法。

| 原书章节或理法 | 程序提供的结构 | 仍须查原文判断的条件 |
| --- | --- | --- |
| 六神之象 | 六神落爻、六亲与世应 | 对应人物、场景及具体象义 |
| 组合之象 | 18条组合前提逐项检查 | 场景、取用、旺衰和例外 |
| 长生十二宫 | 各爻相对日月、其他爻及本位变爻的十二阶段 | 是否实际发生入墓、绝处逢生等作用 |
| 三刑之象 | 三支组合、两支关系、子卯刑、双刑、自刑支 | 本作者的定义、作用条件及对应事件 |
| 伏神之象 | 伏神排盘、飞伏五行关系 | 伏神取用与能否出伏 |
| 旬空之象 | 各爻旬空事实 | 真空、假空、填实与具体场景 |
| 卦之反吟 | 上下卦、卦变方位关系 | 对象、反复原因和吉凶 |
| 进退位之象 | 同类爻之间的变支与爻位比较 | 是否代表可比较的对象 |
| 隔山化爻 | 变支衔接另一动爻的有向链及顺逆方向 | 链条取用及实际含义；不视为直接回头生克 |
| 六害之象 | 生中带害、克中带害、纯相害和全化害 | 生克效力、对象和场景 |
| 卦象参考意义 | 本变卦、上下卦和宫位 | 卦名对应的象义，不能由卦名直接断事 |
| 其他理法 | 爻变反吟、伏吟、三合与半合支组候选 | 暗动、空破墓与成局时点 |

`build_chart(..., yongshen_positions=[3])`里的爻位是调用方根据取用依据给出的候选，程序不自行选用神。返回的`patterns.facts`包含参与爻位、作用方向和`source_rule_id`；可直接用`get_source`回查。`features.pattern_ids`可传给案例检索寻找同类结构。

`combination_checks`区分`structural_match`、`needs_yongshen`、`not_detected`。`structural_match`只表示盘面前提命中，不能等同于完整格局成立，更不能直接推导吉凶。单支自刑、同五行双刑按所附书籍体系标注，与其他流派不同之处保留说明。

## 逐字校订与查询

三本811页均有机器对照底稿；严格逐字校订持续分批进行，唯一进度台账为[OCR逐字校对进度](OCR逐字校对进度.md)。逐字查看原图后保存整页文字、图表转写、来源哈希和疑点。页码残缺保留校注，不凭经验补齐。

检索和原文回查返回`page_reviews`。有已核准页ID时，调用：

```python
get_source("page:liuyao_lifa_jinjie:18")
```

普通证据继续使用稳定的原文行号和现有解析记录；整页稿独立返回，不把排版重排静默套到旧行号上。已核准整页不意味着案例JSON已逐字段复核。行级修订须另外核准，未核准的机器术语建议不进入正文。普通证据可用`text_version="original"`查看修订前OCR。

本次程序测试验证分类路由、公共规则处理、结构召回、原文引用及校订状态边界；不作为预测准确率或全部语义标签正确性的证明。
