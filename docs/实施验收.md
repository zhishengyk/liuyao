# 实施验收

本文记录0.3.0的交付边界。默认发布基线为宿主AI组织检索＋本地BM25/结构匹配，不将实验向量代码说成已完成的语义检索服务。

## 已验证的内容

- 六份固定来源、811个OCR页码锚点；重建得到2,139个知识块和1,548条候选卦例。
- 原文、行号/页码、来源哈希与结构化字段分开保留；候选记录的缺失和冲突不自动消除。
- 排盘覆盖64卦八宫、4,096种动变组合、纳甲、六亲、世应、六神、伏神、旬空和历法边界。
- 对照用户排盘图片：2026-09-05 01:27北京时间，巽为风初爻动变风天小畜；四柱、农历、本变卦世应和六神逐项测试。
- 排盘返回结构化JSON和`display.markdown`，上爻到初爻展示，图片中的私人占问和头像未用于公开示例。
- 论述/案例分路查询，默认12＋8，可提高数量、按ID补查去重、按作者/方法/占类过滤并回查原文。
- 更新后的工作区35项自动测试通过；插件清单和Skill校验通过。
- `--self-check`在本地检查排盘、12条论述、8个案例和原文出处，不调用模型。
- SQLite向量查询用真实sqlite-vec扩展验证了过滤、多窗口合并和只读查询；模型编码与神经重排测试仍使用替身。

## 发布入口

GitHub目录由`.agents/plugins/marketplace.json`声明，名称`liuyao`。插件固定指向匹配版本的服务包，`scripts/install_release.ps1`使用Codex原生命令串联目录刷新、程序准备、离线自检与插件安装。

发布工作流需要完成Linux建库/测试、sdist/wheel/插件ZIP构建、uvx协议调用和离线复测。实际发行物以[GitHub Release](https://github.com/zhishengyk/liuyao/releases/tag/v0.3.0)及工作流结果为准。

## 使用效果与尚未完成项

历史开发验收保留过20条宿主AI分析和80次工具调用，以及61个来源锚点代理问题与1,952条引文检查。这些是开发快照证据，不是0.3.0的预测准确率或人工相关性金标。新版可通过下面的命令重新运行代理评测。

- 桌面端和VS Code的界面操作由用户手动验收，不以CLI成功替代；IDE使用MCP，桌面端/CLI可用插件。
- 全库真实语义编码、轻量查询编码器与神经reranker尚未完成，默认包不安装这些模型。
- 不提供常驻自动更新器，也未证明所有Codex版本都会自动同步GitHub插件更新。
- 书籍OCR正确性、作者反馈真实性与预测有效性未经过独立验证。

## 复查命令

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m liuyao_mcp.server --self-check
.\.venv\Scripts\python.exe -m liuyao_mcp.evaluate
codex plugin list --json
```

运行中的旧MCP进程可能占用开发数据库。发布构建使用独立的`.local/release-data/`；若要重建开发库，先结束使用该库的旧服务，或给建库命令指定另一个输出路径。源码测试可用`LIUYAO_DB`指定刚重建的数据库，避免把旧进程持有的开发快照误作新版本。
