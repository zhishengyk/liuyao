# 实施验收

本文记录0.5.0的交付边界。默认发布基线为宿主AI组织检索＋本地BM25/结构匹配，不将实验向量代码说成已完成的语义检索服务。

爻值统一使用0老阴、1少阳、2少阴、3老阳，输入、每爻value、line_values、卦例JSON和数据库一致，不保留转换层或重复输入字段。已对照修改前的4,096种动变组合，本变卦、世应和盘面特征全部一致；全部1,548条候选卦例已重建为schema_version=0.2，数量与解析状态分布保持不变。40项测试通过。README采用AI按需多角度检索的说明，不固定展示检索数量。

## 已验证的内容

- 六份固定来源、811个OCR页码锚点；重建得到2,188个知识块和1,548条候选卦例。
- 原文、行号/页码、来源哈希与结构化字段分开保留；候选记录的缺失和冲突不自动消除。
- 排盘覆盖64卦八宫、4,096种动变组合、纳甲、六亲、世应、六神、伏神、旬空和历法边界。
- 对照用户排盘图片：2026-09-05 01:27北京时间，巽为风初爻动变风天小畜；四柱、农历、本变卦世应和六神逐项测试。
- 排盘返回结构化JSON和`display.markdown`，上爻到初爻展示，图片中的私人占问和头像未用于公开示例。
- 论述/案例按需查询，Skill与MCP指引要求AI每次主动选择limit，根据证据缺口调整数量、去重补查并回查原文；未传limit时保留12条论述/8个案例的兼容默认值。
- 更新后的工作区40项自动测试通过；插件清单和Skill校验通过。
- 0.4.2通过真实stdio调用验证每轮显式调整limit、跨轮exclude_ids去重以及max_chars不足时返回budget_skipped。AI的具体检索数量由提示指引和本次问题决定，未把接口测试等同于所有问题的证据充分性验证。
- `--self-check`在本地检查排盘、12条论述、8个案例和原文出处，不调用模型。
- SQLite向量查询用真实sqlite-vec扩展验证了过滤、多窗口合并和只读查询；模型编码与神经重排测试仍使用替身。

- 0.5.0按用户提供的上下册PDF核对119个目录条目，并保存2个册节点。修复螣蛇、病、墓、艮宫等章节边界，保留原OCR正文和原文定位。
- 新增get_outline、目录范围检索、场景短语索引、关联案例和导语回查；验证事项过滤不会作用于method=xiangfa，目录后代过滤、分页、去重及长度预算均有测试。
- 目录印刷页码与正文PDF页码分别保留；下册“心里没底”“不诚心”两个目录页码与实际正文不同，已按PDF核对记录，未机械套用目录页码定位。

## 发布入口

GitHub目录由`.agents/plugins/marketplace.json`声明，名称`liuyao`。插件固定指向匹配版本的服务包，`scripts/install_release.ps1`使用Codex原生命令串联目录刷新、程序准备、离线自检与插件安装。

发布工作流需要完成Linux建库/测试、sdist/wheel/插件ZIP构建、uvx协议调用和离线复测。实际发行物以[GitHub Release](https://github.com/zhishengyk/liuyao/releases/tag/v0.5.0)及工作流结果为准。

0.5.0的[Release工作流34438857256](https://github.com/zhishengyk/liuyao/actions/runs/34438857256)全部成功，包含40项测试、目录与场景检索的MCP协议调用、真实Release首次下载及同命令断网复测。预建库包含121个目录节点（119个目录条目与2个册节点）、2,188个知识块及1,548条候选卦例。运行环境不依赖核对时使用的PDF或PDF处理工具。

Windows本机也从实际0.5.0 Release URL完成首次下载，随后阻断HTTP/HTTPS代理，以同一插件命令复测通过；两次均调用排盘、目录浏览、场景／论述／案例检索及原文导语回查。

0.4.2的[Release工作流34433669586](https://github.com/zhishengyk/liuyao/actions/runs/34433669586)全部成功，包含建库、36项测试、真实Release首次下载与同命令断网复测。此版本同步发布按证据需要调整检索数量的Skill、MCP说明和工具描述。

0.4.1的[Release工作流34339772967](https://github.com/zhishengyk/liuyao/actions/runs/34339772967)全部成功，包括独立uv缓存下从真实Release下载，以及同一插件命令在阻断HTTP/HTTPS代理后的复测。Windows本机先验证空缓存安装与断网调用，再用发布后的实际插件配置启动：首次下载约36秒，随后阻断网络复测通过，两次均完成排盘、论述/案例检索和原文回查。测试未通过额外添加`--offline`改变插件启动行为；首次下载允许联网，工具查询使用本地数据库。

0.3.0已完成正式发布：[Release工作流34331345171](https://github.com/zhishengyk/liuyao/actions/runs/34331345171)全部步骤成功，发布安装脚本、插件ZIP、服务包和校验文件。下载实际Release安装脚本并校验SHA256后，在Windows完成程序准备、离线自检及`liuyao-assistant@liuyao`安装，版本0.3.0已启用。首次准备曾遇到uv临时PE文件写入错误，重跑后成功，未把首次失败记为通过。

## 使用效果与尚未完成项

历史开发验收保留过20条宿主AI分析和80次工具调用，以及61个来源锚点代理问题与1,952条引文检查。这些是开发快照证据，不是0.3.0的预测准确率或人工相关性金标。新版可通过下面的命令重新运行代理评测。

- 桌面端和VS Code的界面操作由用户手动验收，不以CLI成功替代；IDE使用MCP，桌面端/CLI可用插件。
- 全库真实语义编码、轻量查询编码器与神经reranker尚未完成，默认包不安装这些模型。
- 已核对本机CLI 0.153.0对应源码，原生支持启动时更新Git插件目录及已安装插件缓存；0.4.1使用版本化wheel接通新版程序和数据库的首次下载，增加真实Release下载及同命令阻断网络复测，不增加自定义更新器。桌面端原生更新的实际触发与界面生效仍由用户验收，详见[插件安装与分发](Codex插件接入与分发.md)。
- 书籍OCR正确性、作者反馈真实性与预测有效性未经过独立验证。

## 复查命令

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m liuyao_mcp.server --self-check
.\.venv\Scripts\python.exe -m liuyao_mcp.evaluate
codex plugin list --json
```

运行中的旧MCP进程可能占用开发数据库。发布构建使用独立的`.local/release-data/`；若要重建开发库，先结束使用该库的旧服务，或给建库命令指定另一个输出路径。源码测试可用`LIUYAO_DB`指定刚重建的数据库，避免把旧进程持有的开发快照误作新版本。
