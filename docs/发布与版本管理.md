# 发布与版本管理

发布渠道为 GitHub Releases；无需 PyPI 账号。发布包包含 Python 服务及预建 SQLite，SQLite 已存储全文和证据定位，因此运行时无需原始资料目录。默认 BM25，语义模型和本机索引不进入发布包。

## 版本规则

服务版本的唯一来源是 `src/liuyao_mcp/__init__.py` 的 `__version__`，打包元数据、`--version` 和 MCP 握手均使用它。插件清单版本同步修改。

- `0.2.1`：兼容修复、资料纠错。
- `0.3.0`：新增功能或较大的检索改进。1.0 之前的破坏性修改也提升次版本并写明迁移方法。
- `1.0.0`：稳定接口首版；此后的破坏性修改提升主版本。

知识库随代码版本发布，资料更新同样发新版。已发布的 tag 和资产不覆盖，有问题发下一个补丁版。`main` 是开发分支，用户自动更新只跟随正式 Release。

## 发布新版

1. 修改代码/资料、版本号、插件清单和 `CHANGELOG.md`。
2. 本地安装开发依赖并测试；提交本次改动。
3. 推送提交及同名版本标签，例如：

```powershell
git push origin main
git tag -a v0.2.1 -m "Release v0.2.1"
git push origin v0.2.1
```

GitHub Actions 的 `Release` 工作流自动检查 tag 与包版本一致，重新建库，运行测试，构建 sdist/wheel，在源码目录外通过 uvx 验证三个 MCP 工具，然后创建 Release 并上传安装包和 SHA256SUMS。任一步失败都不会创建 Release。仓库需允许 Actions 执行；本地推送账号需具有仓库写权限以及更新工作流的权限。

固定名 `liuyao-mcp.tar.gz` 供 latest 下载地址使用，内部包元数据保留真实版本号；同时提供带版本号的 tar.gz 和 wheel。通过 Actions 手动运行只生成构建产物，不正式发布。

## 更新和回退

最新版启动：

```powershell
uvx --python 3.11 --refresh-package liuyao-mcp --from https://github.com/zhishengyk/liuyao/releases/latest/download/liuyao-mcp.tar.gz liuyao-mcp
```

固定版本：

```powershell
uvx --python 3.11 --from https://github.com/zhishengyk/liuyao/releases/download/v0.2.0/liuyao-mcp.tar.gz liuyao-mcp
```

修改 MCP 启动参数后重启服务即可；追加 `--version` 可以检查所用版本。若将来发布到 PyPI，可简化为 `uvx liuyao-mcp@latest`，当前不能使用这个短命令。

## 本地构建验证

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[test]' build uv
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/build_release.py
.\.venv\Scripts\python.exe scripts/smoke_release.py .\.venv\Scripts\uvx.exe --python 3.11 --from "$PWD/dist/liuyao-mcp.tar.gz" liuyao-mcp
```

`dist/` 和生成的包内 SQLite 不提交 Git，由发布时重建。`LIUYAO_DB` 可指定外部数据库，`LIUYAO_ROOT` 可切回源码数据；普通使用者不需要设置。源码开发安装脚本继续使用本地虚拟环境。
