# 断卦与条件审查流程

MCP负责排盘和资料访问，当前助手负责取用、解释和综合，无需另配模型API Key。实际断卦先按SKILL.md内联的核心顺序与[王虎应式全局断卦推理内核](reasoning-kernel.md)形成主线：明确原问与时间尺度 → 取用神 → 日月定根 → 动爻看发展趋势 → 用神自发动则看本位变爻变化 → 过相关性/效力/特殊结构三道门 → 始终核世爻与用神关系 → 形成结果路径和轻重 → 再定向核验王虎应原文 → 理象分工并取应期。本文件只负责复杂冲突、链路审计和批量评测时的条件审查，不另起一套断卦流程。原书GLOBAL与领域原文是证据层，用于核验取用、作用权、事项例外与应期，不替代前置推理主线。普通单题保留必要依据；独立复核与完整JSON记录用于用户要求的批量审计或复杂冲突。

## 先建立分析主线

1. **先明确原问与来意。** 分开现状描述、事件最终结果、求测人得失或喜忧、原因、具体对象/地点和应期；只列原问需要的维度。记录`question_mode=outcome|state_description|cause|timing`、`question_granularity=general_state|specific_event`、`question_focus=primary|secondary`、`time_horizon=now|stage|long_term`、`cast_context=initial|repeat_same_question|followup_new_dimension`。复合题逐项重新取用；兼问不机械套专测极端断法；泛测与“此次”、初占与重复复占分别审查。
2. **再做盘面预扫描并核动变边界。** 先确认年月日、六神、世应、六亲、旬空、月破、暗动/日破候选、伏神、明动及本位变爻，形成`chart_prescan`；此步只记事实，不下吉凶。取用以后，与用神、元忌、世爻直接关系、结果承载和事项专门规则无关的异常可停止跟踪。程序事实、作者规则和当前解释分开；变爻五行作用只核本位动爻，不把它当可跨位发动的普通动爻。
3. **取用并建立对应。** 回查王虎应取用依据，明确`primary_yongshen`并单列`secondary_carriers`，同时给`subject_carrier`、`event_carrier`、`result_carrier`、世应及必要辅助爻明确现实角色、爻位和primary/hidden/changed层次。关系身份和事件承载不得机械混同，例如“朋友借钱”中的朋友可由应爻承载，而钱款结果仍围绕财；“孩子学习”中子孙可代表孩子本人、父母代表学习/成绩，不能仅凭父母克子孙就断成绩差。五行结构存在后仍须通过现实语义相关性审查。用神两现时按王虎应动、空破、冲合、世应、爻位等启发式判断，并允许特殊情况下兼看。元忌是相对已选用神的作用角色，不由六亲名称直接决定吉凶。现实对应尚未成立时先查这一缺口。
4. **按“根—趋势—变化”建立暂定路径。** 先以月建、日辰建立`root_state`，不把旺衰折算成单一分数；年太岁、时辰默认只记`temporal_context`，除非年运、太岁入爻、应期或王虎应事项规则明确要求，不能与月日同权参与“有根/无根”。再看动爻/暗动的`moving_trend`。一个动爻可以同时形成多条候选生克冲合，不能假定只有唯一去向。若用神自身发动，另建`self_transition`读取本位变爻。每条候选关系依次过`relevance_gate`和`effect_gate`，标准化为含现实角色的施力者→受力者，并记录利益流向。关键爻/边拆开记录`force_state`、`semantic_state`、`timing_state`，避免把空破墓等状态直接等价为当前无力；连续相生/贪合忘生等用`chain_validation`逐边核验。变爻五行作用只反馈本位动爻；“动化某六亲”的事件象另列`transformation_semantics`。最后过`special_case_gate`：独发、过旺/过弱、近久病、专测/兼问等命中时，回查王虎应明示例外，不把一般无根或旺衰规则写死。
5. **并列结果路径，并必查世而不让世抢用。** 所有预测记录`shi_relation`，用于求测者立场、心态、努力、承接能力和阶段信息；但主吉凶仍围绕用神。非本人为主用的事项，普通世旺世弱不作为第二张吉凶票；只有世本身为用神，或世动/空破/与用神存在当前事项直接相关作用，或领域专门规则明确要求世应时，才提高主判权重。对每个维度保留当前状态、最终结果、原因和未来变化；久远维度额外查元神/根源持续性与潜伏忌神未来得时。标`effect_degree`区分全部/部分、轻/重、延迟/降级/反复。案例机制只能生成待核路径，不能单独推出结论。
6. **再补领域规则并审理象分工。** 前面的角色消歧和原因识别可使用爻位、六亲扩展象义、六神等；理与象允许同时成立，不把“生”与“墓”等视为互斥状态。默认主吉凶仍围绕用神、日月根基、动爻趋势、元忌与本位动变。若王虎应对独发、近病/久病、天气等明确给出“象直接参与吉凶”的条件，则建立`xiang_outcome_exception`。六神通常主性质/原因，不凭单一六神断成败。
7. **将未来触发纳入结果，再取应期。** 先过`timing_relevance_gate`：候选日期必须来自已经决定当前结果维度的用神、元忌、门控或状态转移。再找“当前最影响用神的条件”，问它何时解除、兑现或得失势；这比见空就报填实、见破就报实破更优先。化进退、出空、合破、冲开、克神受制、元神恢复等若改变结果路径，必须先参与方向综合。近事与远事分层，不把目下吉直接外推久远；不先选日期再倒推事件。
8. **查真冲突，再回到原问作答。** `repeat_same_question` 先核复占资格：前卦已清晰则后卦不能当独立投票；前卦不清时后卦可换角度补信息，但必须前后照应。 相反证据先对齐有向关系的施力者和受力者、现实角色、爻位层次、作者、判断层面（吉凶/细节/应期）、时间范围和前提；任何一项不同都先记录差异，不能混成一票正、一票反。描述财的可用性与实际收入、描述有能力与实际行为等，也不必然互相否定。确为同一问题的冲突时，回查明确主辅及例外；仍无法取舍才保留未决，不能以“未见唯一公式”跳过总纲查询。每个原问维度都有明确判断或具体未决原因，说明主要依据及能改变首选的反证。不能拿正确的次要条件代替没有答出的核心问题；不能把置信度降低视作命中。对对象和时限明确的二元问句，只要各条已核实结果路径综合后有方向，必须作出该方向的首选判断；未知背景、未决辅助作用或没有穷尽的细节用于降低置信度和列出反证，不得单独把主答改为未决。只有主用神无法取定，或已核实的同层关键证据真正势均力敌、且无机制类比或原文主次可用时，才保留未决。缺口影响结论时，在既定预算内补查一次相关总纲、例外或对应关系；未取得新依据则停止并报告不足。冻结评测禁止补查时遵守限制，不回填反馈。

## 独立条件审查

1. 主助手按原问检索，保留实际排盘、查询、完整原文及来源坐标。问题中的对象、动作、时限和已知背景分别核清。开放问题可以包含少量不同维度的具体描述，逐项给依据；不把多个互相矛盾的猜测当作一个命中，也不只用总体吉凶代替具体情况。
2. 独立审查者先只读原问、盘面和实际返回证据，暂不读主答或待测反馈。若需补查，使用同一版本 MCP，保留新增调用。没有独立助手时，单列一次条件审查，并说明这是同一助手复核。批量评测的选择者、预测者和评分者不得互传隐藏结果。
3. 先从关键原文及共享上下文列出与原问有关的规则分支，再对照盘面，不以已有结论决定保留哪一句。每行只对应一个对象的一条规则分支；保留必要前提之间的且/或关系、例外及作用范围。复合前提分别核对，不能因一项不满足就排除其他独立分支；原文逻辑不清时标未知并保留解释。无关条件可说明理由排除，不把全库每条规则都列为必查项。
4. 用下面的条件记录分清盘面关系、语义适用和最终影响。显爻、同位伏神、实际动爻所化变爻及日月分开；同爻不同角色也分别核对。所有生克先按build_chart.relation_semantics标准化为含现实角色、scope、position的施力者→受力者边；“受生/受克”必须反转箭头。月日、动静爻、变→本、飞伏、元忌→用、世应及其他两爻均不得合并反向关系。每个premise只核一个事实前提，引用必要字段的路径和值，避免复制整爻或整盘。已知事实的状态不能因规则语义、效力或优先关系未定而改为unknown：这些争议分别放在logic、applicability或effect。复合前提各自保留状态，再由原文逻辑决定整体适用性；判断文字必须与字段一致。相同来源可共用引用，但不同对象或状态不能合并成一个总状态。
5. 独立审查者从关键来源逐段反查：相关分支、例外、共享导语和同爻多角色是否都有处置？将对应行号、排除理由及缺口记入source_coverage。再核查已列条件是否用错；不能只检查已有主答或逐行勾选。只给结构提示而没有原文时保留缺口，不能编造规则或宣称已完整核查。
6. 主助手回看原文和字段核对审查意见，为每个重要row_id记录采用、排除或未决及理由。新增发现的相关条件先补行再处置，不能藏在结论中。重要缺证在允许的工具预算内补查；禁止新增调用的冻结评测仅登记缺口，不突破该阶段限制。审查者也可能误读；增加助手数不代表核查完成。
7. 完成条件核对和取舍后再写主答及置信度。结构成立不直接等于吉凶；不同角色如何影响原问须说明。原文明示优先关系时保留其原句和前提，否则保留冲突及有依据的判断倾向，不发明权重或按条数投票。对于对象与时限明确的二元结果题，已经成立且指向一方的主线必须形成首选；未决条件不能写成已排除，但应作为置信度和可推翻条件，而非自动取消首选。只有没有可说明的偏向，或主线本身无法成立时保留无法判断。低、中、高表示本次判断把握，没有校准依据时不编概率。

条件记录（普通答复可简洁记录，批量审计用JSON；来源与字段引用可共用，避免重复整盘）：

- `question_dimensions`：逐项记录现状、最终结果、得失/喜忧、原因、时限及未知背景；另记`question_mode`、`question_granularity`、`question_focus`、`time_horizon`、`cast_context`和结果轻重要求。
- `method_basis`：每条拟进入主判的依据记录`authority_tier=wang_direct|wang_case_specific|classic_endorsed|compare_only`、`source_family`、证据ID与原句、必要修订/例外。只有前三类可进入主判；`compare_only`只用于冲突检测。转载重复内容按同一source_family去重，不按出现次数加权。
- `role_map`：记录`primary_yongshen`、`secondary_carriers`、`yongshen_selection_trace`、`subject_carrier`、`event_carrier`、`result_carrier`、世应和必要辅助对象的现实角色、爻位/层次、取用依据及候选分歧。
- `result_paths`：对每个原问维度分别记录人物状态、事件最终结果、求测人得失或喜忧和未来触发；注明它是直接路径、同构路径、机制类比、反向类比或背景。机制类比必须写共同机制、不同条件及本盘对应，不能只按标题排除，也不能独自决定结论。
- `main_path`：围绕原问记录`root_state`、多条`candidate_edges`、筛选后的`relevance/effect`、`force_state`、`semantic_state`、`timing_state`、`chain_validation`、`self_transition`、`shi_relation`、`special_case_gate`、`xiang_outcome_exception`与`timing_relevance_gate`。每条边保留施力者→受力者现实角色、scope、position和利益流向；变爻本位作用与`transformation_semantics`分开。

- `rows`：每项含唯一`row_id`、`evidence_id`、逐字存在于返回原文的`exact_quote`及来源hash/坐标、`subject`（对象角色、爻位、primary/hidden/changed或日月）、`premises`（各前提对应的原句、实际字段路径/值和met/not_met/unknown）、`logic`（原文且/或关系或解释未决）、`exceptions`（有依据的例外及状态，无则说明）、`applicability`（适用状态及理由）、`effect`（可能影响的原问维度及相反条件）。改写内容另标`paraphrase`，不能放进exact_quote。引用可以共用，但每行的对象和状态必须明确。
- `source_coverage`：对关键来源记录`evidence_id`、`authority_tier`、`source_family`、已核`row_ids`、未纳入分支的原句与理由、未解决的`gaps`。这是本次来源覆盖记录，不证明已穷尽全库或所有象义。
- 综合记录`review_dispositions`：每个重要`row_id`对应采用、排除或未决及理由。逻辑、对象或状态不同的行分别解释；可以共用完全相同的理由，但不能用总状态掩盖其中的未知或独立成立条件。
- `dimension_answers`：原问每个维度对应结论或未决、依据行号及限制。吉凶、现状细节、应期不能互相替代。判断是否命中仍需独立反馈，流程完整不等于结果准确。

批量对照保留最初答案、独立审查和最终答案，分别报告遗漏是否补足、是否引入错误、主答是否改变及实际新增调用。保持题目、反馈标准与版本冻结；已曝光案例只能作开发回归，补对旧题不能计为新的盲测准确率或删除原失败记录。
