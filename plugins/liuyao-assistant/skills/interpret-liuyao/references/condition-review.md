# 断卦与条件审查流程

MCP负责排盘和资料访问，当前助手负责取用、解释和综合，无需另配模型API Key。实际执行先读[全局断卦流程与原文](source-prompts/GLOBAL.md)：它按原书明确的“先取用神—再看旺衰、元忌与动变—理法先定吉凶—再由理及象—最后取应期”的线索排列原书正文。本文件负责把该顺序落实成盘面条件审查；两者都不是各书共同承认的统一公式，也不保证预测正确。普通单题保留必要依据；独立复核与完整JSON记录用于用户要求的批量审计或复杂冲突。

## 先建立分析主线

1. **先明确原问与来意。** 分开人物当前状态、事件最终结果、求测人得失或喜忧、原因、具体对象/地点和应期；只列原问需要的维度。比如“被抓后能否放回”至少分清当前拘押状态与后续释放结果，不能只用当前状态替代最终结果。保留人物关系、行为方向、期限及已知背景，复合题逐项回答。未给期限保持未知，不把现状改成未来潜力，不先猜书例结局再搜证据。
2. **再核盘面事实与动变边界。** 先确认年月日、六神、世应、六亲、动爻及本位变爻；程序事实、作者规则和当前解释分开。变爻仅先核本位动爻，不把它当作可跨位发动的普通动爻。
3. **取用并建立对应。** 回查取用依据，给主用神、世应及必要辅助爻明确现实角色、爻位和primary/hidden/changed层次。元神或忌神是相对已选用神的作用角色，不由六亲名称直接决定吉凶。取用有分歧时保留有依据的候选，分别推演；不能只选最容易得出结论的一爻。五行关系只能说明盘面作用；若要把爻写成警察、拘押机关、同伙、施害者、具体案由或其他现实角色，必须另列场景原文和盘面对应，否则只可保留为低置信候选，不能作为主方向证据。现实对应尚未成立时先查这一缺口。
4. **先以理法判断各路径的暂定状态。** 所有生克先标准化为`施力者(现实角色,scope,position) → 受力者(现实角色,scope,position): 生/克`；“受生/受克”反转箭头。先看日月对用神，再看旺爻、实际动爻及本位变爻对用神的作用；再核元忌、旺衰、空破冲合墓绝和例外。月日、动静爻、变→本、飞伏、元忌→用、世应及其他两爻一律适用。这里先得到人物状态或单条路径的暂定判断；不得把它自动升级为另一维度的最终结果。生克或墓候选成立不等于效力已定；但效力未定也不能抹掉结构事实。先查所选论法的一般原则及对应例外，再判断主次，不按支持条数或检索排名投票。
5. **并列结果路径，并审机制类比。** 对每个原问维度分别保留人物当前状态、事件最终结果、求测人得失或喜忧、原因和未来变化路径。规则或案例条件不完全相同时，不能只按标题或某一前提自动排除；标为`direct`、`same_structure`、`mechanism_analogy`、`reverse_analogy`或`background_only`，并写清共同机制、不同条件和本盘对应。机制类比只能生成待核路径，不能单独推出结论；但也不能因并非完全同构就从最终综合中消失。
6. **再补领域规则、世应与象法细节。** 在各路径已经列出后，才用世应、领域原文、爻位、六亲、六神、五行和状态解释原因或过程。现状/物件/行为题必须围绕现实角色组合这些意义，不要求先硬断吉凶，也不能用总体旺衰替代细节。三刑、六神、长生等通常是细节材料；低置信现实角色或原因不得进入主方向的决定性证据集合。
7. **将未来触发纳入结果，再取应期。** 应期不能只在最终答案后补日期。问能否、能否放回、能否办成等后续结果时，化进退、月破日合、出空、冲开、受克或受生等未来触发若能改变某条结果路径，必须先与暂定状态一起综合，再判断方向。按事情远近和已核实结构给候选时间，不先选日期再倒推事件。
8. **查真冲突，再回到原问作答。** 相反证据先对齐有向关系的施力者和受力者、现实角色、爻位层次、作者、判断层面（吉凶/细节/应期）、时间范围和前提；任何一项不同都先记录差异，不能混成一票正、一票反。描述财的可用性与实际收入、描述有能力与实际行为等，也不必然互相否定。确为同一问题的冲突时，回查明确主辅及例外；仍无法取舍才保留未决，不能以“未见唯一公式”跳过总纲查询。每个原问维度都有明确判断或具体未决原因，说明主要依据及能改变首选的反证。不能拿正确的次要条件代替没有答出的核心问题；不能把置信度降低视作命中。对对象和时限明确的二元问句，只要各条已核实结果路径综合后有方向，必须作出该方向的首选判断；未知背景、未决辅助作用或没有穷尽的细节用于降低置信度和列出反证，不得单独把主答改为未决。只有主用神无法取定，或已核实的同层关键证据真正势均力敌、且无机制类比或原文主次可用时，才保留未决。缺口影响结论时，在既定预算内补查一次相关总纲、例外或对应关系；未取得新依据则停止并报告不足。冻结评测禁止补查时遵守限制，不回填反馈。

## 独立条件审查

1. 主助手按原问检索，保留实际排盘、查询、完整原文及来源坐标。问题中的对象、动作、时限和已知背景分别核清。开放问题可以包含少量不同维度的具体描述，逐项给依据；不把多个互相矛盾的猜测当作一个命中，也不只用总体吉凶代替具体情况。
2. 独立审查者先只读原问、盘面和实际返回证据，暂不读主答或待测反馈。若需补查，使用同一版本 MCP，保留新增调用。没有独立助手时，单列一次条件审查，并说明这是同一助手复核。批量评测的选择者、预测者和评分者不得互传隐藏结果。
3. 先从关键原文及共享上下文列出与原问有关的规则分支，再对照盘面，不以已有结论决定保留哪一句。每行只对应一个对象的一条规则分支；保留必要前提之间的且/或关系、例外及作用范围。复合前提分别核对，不能因一项不满足就排除其他独立分支；原文逻辑不清时标未知并保留解释。无关条件可说明理由排除，不把全库每条规则都列为必查项。
4. 用下面的条件记录分清盘面关系、语义适用和最终影响。显爻、同位伏神、实际动爻所化变爻及日月分开；同爻不同角色也分别核对。所有生克先按build_chart.relation_semantics标准化为含现实角色、scope、position的施力者→受力者边；“受生/受克”必须反转箭头。月日、动静爻、变→本、飞伏、元忌→用、世应及其他两爻均不得合并反向关系。每个premise只核一个事实前提，引用必要字段的路径和值，避免复制整爻或整盘。已知事实的状态不能因规则语义、效力或优先关系未定而改为unknown：这些争议分别放在logic、applicability或effect。复合前提各自保留状态，再由原文逻辑决定整体适用性；判断文字必须与字段一致。相同来源可共用引用，但不同对象或状态不能合并成一个总状态。
5. 独立审查者从关键来源逐段反查：相关分支、例外、共享导语和同爻多角色是否都有处置？将对应行号、排除理由及缺口记入source_coverage。再核查已列条件是否用错；不能只检查已有主答或逐行勾选。只给结构提示而没有原文时保留缺口，不能编造规则或宣称已完整核查。
6. 主助手回看原文和字段核对审查意见，为每个重要row_id记录采用、排除或未决及理由。新增发现的相关条件先补行再处置，不能藏在结论中。重要缺证在允许的工具预算内补查；禁止新增调用的冻结评测仅登记缺口，不突破该阶段限制。审查者也可能误读；增加助手数不代表核查完成。
7. 完成条件核对和取舍后再写主答及置信度。结构成立不直接等于吉凶；不同角色如何影响原问须说明。原文明示优先关系时保留其原句和前提，否则保留冲突及有依据的判断倾向，不发明权重或按条数投票。对于对象与时限明确的二元结果题，已经成立且指向一方的主线必须形成首选；未决条件不能写成已排除，但应作为置信度和可推翻条件，而非自动取消首选。只有没有可说明的偏向，或主线本身无法成立时保留无法判断。低、中、高表示本次判断把握，没有校准依据时不编概率。

条件记录（普通答复可简洁记录，批量审计用JSON；来源与字段引用可共用，避免重复整盘）：

- `question_dimensions`：逐项记录人物当前状态、事件最终结果、求测人得失或喜忧、原因、时限及未知背景；同一原问可以有多个维度，不能用人物当前状态替代后续结果。
- `method_basis`：各作者论法、总纲证据ID与原句、必要修订/例外；真实冲突时记录王虎应优先规则是否触发、所依据的王虎应原句/评释、其他作者结论及未采用原因。
- `role_map`：用神、世应和必要辅助对象的现实角色、爻位/层次、取用依据及候选分歧。
- `result_paths`：对每个原问维度分别记录人物状态、事件最终结果、求测人得失或喜忧和未来触发；注明它是直接路径、同构路径、机制类比、反向类比或背景。机制类比必须写共同机制、不同条件及本盘对应，不能只按标题排除，也不能独自决定结论。
- `main_path`：围绕原问的关键有向作用链和判断层面；每个生克边保留施力者→受力者的现实角色、scope、position，注明依据行号、实际效力、主辅或例外。现实角色若不是直接取用，另列场景原文；缺乏场景原文的候选不能进入主方向。这里是简洁可核对的分析依据，不要求展开所有内部推理。

- `rows`：每项含唯一`row_id`、`evidence_id`、逐字存在于返回原文的`exact_quote`及来源hash/坐标、`subject`（对象角色、爻位、primary/hidden/changed或日月）、`premises`（各前提对应的原句、实际字段路径/值和met/not_met/unknown）、`logic`（原文且/或关系或解释未决）、`exceptions`（有依据的例外及状态，无则说明）、`applicability`（适用状态及理由）、`effect`（可能影响的原问维度及相反条件）。改写内容另标`paraphrase`，不能放进exact_quote。引用可以共用，但每行的对象和状态必须明确。
- `source_coverage`：对关键来源记录`evidence_id`、已核`row_ids`、未纳入分支的原句与理由、未解决的`gaps`。这是本次来源覆盖记录，不证明已穷尽全库或所有象义。
- 综合记录`review_dispositions`：每个重要`row_id`对应采用、排除或未决及理由。逻辑、对象或状态不同的行分别解释；可以共用完全相同的理由，但不能用总状态掩盖其中的未知或独立成立条件。
- `dimension_answers`：原问每个维度对应结论或未决、依据行号及限制。吉凶、现状细节、应期不能互相替代。判断是否命中仍需独立反馈，流程完整不等于结果准确。

批量对照保留最初答案、独立审查和最终答案，分别报告遗漏是否补足、是否引入错误、主答是否改变及实际新增调用。保持题目、反馈标准与版本冻结；已曝光案例只能作开发回归，补对旧题不能计为新的盲测准确率或删除原失败记录。
