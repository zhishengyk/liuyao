# 外部书例盲测集 v1

本目录收录 27 条库外书例：刘汶德《卦技二十法》9 条（其中 1 条为陶曙光来信），《邵伟中六爻预测特训班讲义》9 条，李顺祥《六爻详解》9 条。另保存 3 条未纳入评分的残缺 OCR 候选。原文均为本地资料，没有加入 `data/sources.jsonl` 或知识库。

这里的“反馈”是书中报告，未经独立事实核实。该集合可评估检索、排盘、证据引用与模型对书中结果的吻合度，不能证明占卜能预测现实。样本经过出版者和本次整理者筛选；无法排除模型预训练见过原书。27 条不是 27 次新开展的前瞻实验。

## 文件与隔离

- `development.blind.jsonl`：14 条开发输入，可用于诊断修复。
- `development.key.jsonl`：14 条开发答案、证据及评分目标。
- `holdout.blind.jsonl`：13 条最终盲测输入。
- `holdout.key.sealed.jsonl`：13 条封存答案，只供冻结预测后的评分阶段读取。
- `semantic_challenges.jsonl`：27 条人工阅读后拟定的自然表述检索问题，以及独立的预期主题/结构需求。不是从检索命中的词反推问题。
- `validation_report.json`：排盘交叉校验、签名去重、文本重合审计与六源数据库快照哈希。
- `frozen_manifest.json`：评估文件哈希，用于固定盲测版本。
- `candidates_*.json`：含答案的完整人工整理候选，**不得提供给预测上下文**。

“封存”是评估流程隔离，没有加密或文件系统访问控制。预测代理应在全新上下文中只收到 blind 记录，并只允许调用当前六源知识库检索工具；禁止读取 key、候选、此目录其他文件、原书和网络搜索原例。评分代理在预测已落盘后读取 key。不要根据 holdout 结果调整本轮方法后重跑并仍称首次盲测；若重复使用，标记为开发资料并另建新的最终集合。

同一案例没有拆成多个独立样本：摸奖的后续戌日追问不另计数；李书同人多校录取组未纳入，只选起卦日期不同的另一例。李顺祥整本文档只进入最终 holdout；刘、邵各有少量预先固定留出例。这样既有跨作者测试，也覆盖失物、行人、天气、兄弟病与官运等题目。

## 输入及核验标准

六爻从初爻到上爻：`0` 老阴、`1` 少阳、`2` 少阴、`3` 老阳。时间均采用原书明确的月支、日干支；缺少精确钟点时不伪造公历起卦时刻。

每条入选例均有完整六爻、合法月日、问题及书中后续结果，机械排盘与本卦、本爻纳支和动爻所成变卦一致。源文的字形/纳甲局部错误原样保留并标注，未将源文每个字段都宣称为无误。刘书有两例未列卦名，以六个清晰爻符、纳支及正文卦象复核；`gua05` 变卦栏沿用了原支，六个原始爻符和“泰之复”标题一致，不能把该栏当作标准变卦纳甲。

李顺祥资料属于 OCR。原书引用的页面图像在本地缺失，9 条入选例只完成**文本交叉核验**，没有完成原图核验；顿号/逗号、己/已/巳、卯/卵等可读字形处理均记在 `validation_notes`。3 条存在缺爻符或冲突的候选明确排除，不能用本变卦名推导补出的爻值冒充原文已核实。若后续要求“全部源图核验”，当前只能报告 18 条原生文本已核验与 9 条 OCR 文本交叉核验，不能声称 27 条都经过源图确认。

答案分别列 `pre_existing_facts`、`later_feedback`、`scoring_targets`。已知诊断、婚史、当前男友、起卦前经营收入不计成后续预测；明确的随后死亡、再婚、找回、停业、盈亏、录取等才计分。有干预建议的案例只评价实际采取选择后的结果，不能验证未实施选择的反事实。

## 评分方式

预测应先保存为记录：`case_id`、`primary_prediction`、`timing_prediction`、`optional_details`、`confidence`、`abstentions`、`source_ids`、`source_quotes`、`reasoning_summary`。不要求逐步内部思维，只要可审查的规则与判断依据。

主结果、时间、额外细节分别评分，不以一句宽泛吉凶代替全问，也不把某个细节猜对当作全例正确。每个目标使用 `correct / incorrect / abstain / not_scored`，记录总分母和弃答数；不能只报非弃答准确率。来源相关性、引文是否支持推断单独评分，检索命中不等于预测正确。

`li01` 农历日期存在书内冲突，时间不评分；`li04` 只评分后续停业，早期收益时序不清；`gua06` 书中预言当夜接回但仅有消息反馈，接回不评分；`shao05` 破财没有明确反馈，财损不评分；`shao02` 戌日再摸奖另作附录事实，主评分只看占日。

## 去重与再验证

验证脚本读取当前六源数据库，检查：来源路径/整文件哈希不属于训练来源；`月支 + 日干支 + 六爻值` 不与训练例或集合内重复；案例原文以 32 个规范化字符、步长 8 检查与六份训练全文的连续重合。本次 27 条均无签名重复和该阈值的文本重合。该方法可发现直接复制，不能保证发现所有改写、OCR 差异或未被原解析器提取的同源例。审计只描述六源本地库，不能证明基础模型训练集未见过这些故事。

从仓库根目录运行（Windows 虚拟环境）：

```text
python -c "import runpy,sys; sys.path.insert(0,'src'); runpy.run_path('scripts/validate_external_cases.py',run_name='__main__')"
```

脚本不修改生产代码或训练数据库，只重写本目录派生评估文件。知识库重建后须再运行一次检查，并在开始最终盲测之前冻结新哈希。正式开始后禁止重新生成或更改盲测输入与答案。
